# 非洲网吧跑刀记 2.0 TapAI 修改总方案

日期：2026-06-16  
用途：提交给 Tap 制造 AI 进行整合修改  
版本目标：从当前 1.5/1.6 推进到真正 2.0  
核心原则：第一季完整闭环，结局后继续经营，多城市长期扩展。

## 0. 给 TapAI 的总指令

请不要只新增文案，也不要只做 UI 美化。本次要把当前已有系统整合成完整 2.0：

1. 统一 UI 和弹窗规则。
2. 接通选择后果账本。
3. 补完 D15-D30 第一季强主线。
4. Day30 固定进入第一季多结局。
5. 第一季结局后允许玩家继续经营。
6. 打开 D31+ 多城市经营入口。
7. 把网吧升级体系接入战队成长、比赛结果、事件选择和结局分流。

不要重做底层。保留现有经营、战队、AEL、Victor、分店、转生、地图、升级、事件系统，在现有代码上补齐逻辑链。

## 1. 2.0 的准确定义

2.0 不是“做完 7 城电竞帝国”，也不是“30 天后游戏结束”。

2.0 要做到：

> 玩家在 D1-D30 走完第一季：背井离乡开破网吧，发现 Kofi，组建 Dragon Force，被 Victor 压迫，打进 AEL，做出一系列现实选择，并在 D30 得到第一季多结局。之后玩家可以带着这个结局继续经营，去多城市开网吧。

版本边界：

- D1-D30：第一季完整体验。
- D30：第一季多结局，不是删档终局。
- D31+：继续经营，进入多城市经营。
- 多城市：2.0 做最小可玩入口，不要求完整 7 城终局。
- 长期世界赛、7 城帝国、地下帝国终局：留到 2.5/3.0 扩展。

## 2. 当前代码存在的问题

当前版本已有很多 2.0 零件，但逻辑还没有完全打通。

### 2.1 多结局不是完全摆设，但不是第一季多结局

当前部分选择会写入：

- `karma`
- `reputation`
- `specialization`
- `communityRoute`
- `kofiTrust`
- `aelRegistered`

这些字段能影响部分老结局，所以不是完全摆设。

但当前缺口是：

- D30 不会固定进入第一季多结局。
- 第一季多结局没有单独系统。
- `ethicsLedger` 没有稳定参与结局判定。
- `ethics = {...}` 字段大多只是事件上的标注，没有被通用事件处理器自动写入账本。

### 2.2 D15-D30 还不是强主线

当前 D15-D30 有很好的明日预告和条件事件池，但缺“每天必到”的主线事件。

需要补：

- D15-D30 固定主线事件。
- AEL 赛程推进。
- Kofi 压力变化。
- Victor 正面对抗。
- Day30 决赛和结局。

### 2.3 多城市不是第一季后的自然继续

当前已有：

- 分店系统：可在不同地点开分店，有被动收入。
- 转生系统：可解锁新城市，但会把 `day` 重置为 1，清空队伍和分店。

这两套都能用，但都还不是玩家想要的：

> 第一季结束后，我带着自己的结局和资源继续经营，并去多城市开网吧。

2.0 需要新增“D31+ 多城市继续经营”层，不要直接把转生当成第一季后续。

### 2.4 UI 弹窗还会叠太多

当前 BuildUI 仍可能叠加：

- 明日预告。
- DayStart。
- 门口闲聊。
- 日总结。
- 周报。
- 行动结果。
- 成就。
- 广告。

2.0 要规范弹窗，否则内容越多体验越乱。

### 2.5 网吧升级和游戏核心挂钩不够

当前升级更像经营数值：

- 多收入。
- 增容量。
- 减损耗。

但玩家真正关心的是：

- 升级电脑后 Kofi 是否不卡了？
- 网络升级是否影响 AEL 比赛？
- 发电机是否能防止决赛停电？
- 安保是否能防 Victor 破坏？
- 环境是否能减少队员疲劳？

2.0 要把网吧升级体系和战队、比赛、事件、结局绑定。

## 3. UI 和弹窗规范

这是 2.0 的硬规则。

### 3.1 弹窗总规则

1. 事件必须有弹窗反馈。
2. 玩家点击“结束今天”之后，只出现一个“今日总结弹窗”。
3. 不再增加“每天进入时弹窗”。
4. 不再增加“每天结束后的额外剧情弹窗”。
5. 所有事件弹窗、总结弹窗、tag 详情都必须一屏放下，不依赖纵向滑动。
6. 广告弹窗、福利弹窗不能压过主线反馈。

### 3.2 只保留四类核心弹窗

| 弹窗类型 | 触发时机 | 作用 | 是否滑动 |
| --- | --- | --- | --- |
| 事件选择弹窗 | 主线/街区/行动事件触发 | 给玩家选择 | 否 |
| 事件结果弹窗 | 玩家做出选择后 | 告诉玩家后果 | 否 |
| 今日总结弹窗 | 点击结束今天后 | 汇总经营、战队、故事、明日钩子 | 否 |
| 第一季结局页 | D30 结算 | 展示结局和继续经营入口 | 可分页，不纵向长滚动 |

### 3.3 禁止的弹窗行为

- 每天一进入游戏自动弹剧情。
- 结束今天后，在总结弹窗之外再弹剧情弹窗。
- 长文案 ScrollView 弹窗。
- 一个弹窗里塞 4 个以上 tag。
- 一个结果弹窗里塞 5 个以上数值变化。
- 事件、广告、福利、系统提示连续弹三层。

### 3.4 文案长度标准

事件选择弹窗：

- 标题：不超过 10 个汉字。
- 正文：90-140 个汉字。
- 选项：2-3 个。
- 每个选项：不超过 14 个汉字。
- 每个选项提示：不超过 18 个汉字。
- tag：最多 3 个。

事件结果弹窗：

- 标题：不超过 10 个汉字。
- 正文：80-120 个汉字。
- 数值变化：最多 4 条。
- 按钮：只保留“知道了”。

今日总结弹窗：

- 经营：收入、支出、现金变化。
- 战队：训练、士气、比赛进展。
- 故事：今天关键选择的一句话余波。
- 明日：一句强钩子。
- 按钮：进入第 X+1 天。

## 4. 选择后果账本

2.0 必须让玩家明确知道：

> 我这个选择以后会有后果。

### 4.1 保留并强化四维伦理账本

使用当前已有字段：

```lua
playerData_.ethicsLedger = playerData_.ethicsLedger or {
    moneyVsPeople = 0,
    legalVsGray = 0,
    integrationVsExtraction = 0,
    resultVsProcess = 0,
}
```

四个维度解释：

- `moneyVsPeople`：重人情 vs 重金钱。
- `legalVsGray`：合法经营 vs 灰色捷径。
- `integrationVsExtraction`：融入本地 vs 榨取本地。
- `resultVsProcess`：重视过程/成长 vs 唯结果论。

### 4.2 必须接通 `ethics = {...}`

当前很多事件 choice 已有：

```lua
ethics = { legalVsGray = -2 }
```

但通用事件处理器没有自动入账。请新增统一函数：

```lua
function ApplyChoiceEthics(choice, eventId, day)
    if not choice or not choice.ethics then return end
    playerData_.ethicsLedger = playerData_.ethicsLedger or {
        moneyVsPeople = 0,
        legalVsGray = 0,
        integrationVsExtraction = 0,
        resultVsProcess = 0,
    }
    for key, delta in pairs(choice.ethics) do
        playerData_.ethicsLedger[key] = (playerData_.ethicsLedger[key] or 0) + delta
    end
    playerData_.ethicsKeyChoices = playerData_.ethicsKeyChoices or {}
    table.insert(playerData_.ethicsKeyChoices, {
        day = day or playerData_.day,
        eventId = eventId,
        choiceText = choice.text,
        ethics = choice.ethics,
    })
end
```

在事件选择执行 `ch.effect` 前后调用，保证所有写了 `ethics` 的选择都会入账。

### 4.3 选择反馈展示

选择前用 tag 提示：

- 影响 Kofi
- 街区支持
- 合法风险
- 灰色捷径
- Victor 注意
- AEL 审查
- 队伍士气
- 多城市伏笔

选择后用结果弹窗展示最多 4 条变化：

```text
现金 -80
Kofi 信任 +5
合法风险 +1
街区支持 +2
```

不要把所有隐藏数值暴露，但要让玩家感受到方向。

## 6. AEL 从赞助系统升级为比赛主轴

当前 `AELSystem.lua` 是赞助/任务系统，可以保留，但 2.0 要新增赛程层。

### 6.1 AEL 关键比赛节点

- D15：报名确认。
- D17：预选赛第一轮。
- D20：资格赛晋级/审查。
- D22：正赛首轮。
- D25：Gold Net 对决。
- D28：半决赛/决赛前夜。
- D30：第一季决赛。

### 6.2 比赛结算公式

比赛不要只看队员技能，要加入网吧设施和选择后果：

```text
比赛实力 =
队员实力
+ 训练状态
+ 网吧设施评分
+ 士气
+ 街区支持
- Kofi 压力
- Victor 干扰
- 灰色/AEL 审查风险
```

这样经营、升级、事件选择都会影响比赛。

## 7. 网吧升级体系和游戏核心挂钩

这是本轮重点。

当前升级体系的感受问题：

> 玩家升级网吧，是为了数字变大，不是为了故事和比赛变强。

2.0 要改成：

> 玩家升级网吧，是为了让 Kofi 能赢，让队伍留下，让 Victor 的压迫失效，让结局变好。

### 7.1 五类升级对应核心影响

| 网吧升级 | 经营效果 | 战队/比赛效果 | 事件/结局效果 |
| --- | --- | --- | --- |
| 电脑 | 增加容量和收入 | 提升训练效率、基础战力 | Kofi 不再卡帧，电竞路线加分 |
| 网络 | 提升口碑和客流 | 降低比赛掉线/延迟风险 | AEL 审查加分，线上赛更稳 |
| 电力/发电机 | 抗停电 | 决赛不被停电影响 | 停电事件可选择“启动备用电源” |
| 空调/环境 | 提高停留和满意度 | 降低疲劳，恢复士气 | 社区/温暖路线加分 |
| 安保/监控 | 降低事故和损失 | 防 Victor 破坏 | 合法路线加分，灰色风险下降 |

### 7.2 新增设施评分

新增函数：

```lua
function CalcFacilityPower()
    local p = playerData_
    local score = 0
    score = score + (p.computers or 0) * 2
    score = score + (p.netSpeed or 1) * 8
    score = score + (p.generatorLevel or 0) * 10
    score = score + (p.acLevel or 0) * 6
    score = score + (p.securityLevel or 0) * 8
    score = score + math.floor((p.equipCondition or 100) / 10)
    return score
end
```

比赛、事件、结局都读取它。

### 7.3 升级解锁事件选择

具体例子：

- 有发电机：D20 审查可选“展示备用供电方案”，降低 `auditRisk`。
- 网络 Lv3：D17/D22 比赛减少掉线惩罚。
- 安保 Lv2：D23/D25 可抓到 Victor 破坏证据。
- 空调 Lv2：D16/D28 加训时降低 Kofi 压力。
- 电脑数量/等级达标：AEL 球探评分提高，Kofi 信任提升。

### 7.4 首页推荐升级

首页升级推荐不要只写“升级电脑”。

改成：

```text
推荐升级：网络 Lv2
原因：AEL 预选赛前，网络稳定会降低掉线风险
影响：比赛稳定 +15%，Victor 破坏风险 -10%
```

推荐逻辑：

- D15-D17 优先电脑/网络。
- D18-D20 优先网络/电力。
- D21-D25 优先安保/网络。
- D26-D30 优先空调/电脑/电力。
- 如果 Kofi 压力高，推荐空调/休息环境。
- 如果 Victor 压力高，推荐安保/监控。

### 7.5 升级参与结局分流

设施路线影响 D30 结局：

- 电脑/网络高：电竞正统路线。
- 空调/环境/社区设施高：街区领袖路线。
- 安保高且合法值高：正面对抗 Victor 路线。
- 安保高但灰色值低：地下路线。
- 分店/商业设施高：商业扩张路线。

## 9. D31+ 继续经营和多城市

2.0 必须做到：第一季结束后还能玩下去。

### 9.1 结局后按钮

D30 结局页提供：

- 继续经营：进入 D31 当前城市。
- 去新城市：进入城市选择/扩张页面。
- 回顾选择：查看第一季关键选择。

### 9.2 不要直接用转生替代继续经营

当前转生会：

- `day = 1`
- 清空队伍。
- 清空分店。
- 重置本地经营。

这可以作为长期玩法保留，但不要作为 D30 后默认入口。

2.0 需要新增“继续经营模式”：

```lua
playerData_.postSeason = true
playerData_.season = 2
playerData_.day = 31
```

玩家保留：

- 当前资金。
- 当前设备。
- 当前队伍。
- 当前分店。
- 第一季结局加成。
- 第一季关键选择记录。

### 9.3 多城市最小可玩

2.0 最小要求：

- 至少 3 个城市可见：拉各斯、内罗毕、开普敦。
- 至少 1 个新城市可实际进入经营。
- 当前城市继续产生收益。
- 新城市可以开第一家分店/新店。
- 城市之间可以切换查看状态。

建议新增：

```lua
playerData_.cityNetwork = playerData_.cityNetwork or {
    current = "wakandaville",
    cities = {
        wakandaville = { unlocked = true, cafes = {...}, reputation = ..., income = ... },
    }
}
```

如果改动太大，可以先复用 `branches`，但要包装成“城市经营页面”，不要只显示分店列表。

### 9.4 第一季结局影响多城市开局

例子：

- 非洲之光：新城市初始社区好感 +20。
- 街区领袖：维护成本 -10%。
- 商业扩张：新城市启动资金 +1000。
- 灰色崛起：启动资金 +1500，但审查风险 +2。
- Victor 的镜子：扩张成本 -15%，队员忠诚 -10。
- 明日再战：Kofi 留队，训练效率 +10%。

### 11.2 事件处理顺序

EndDay 推荐顺序：

4. 如果 D15-D30 有第一季主线，优先触发。
5. 如果 prevDay == 30，触发第一季结局。

7. 随机事件、支线事件只在不抢主线时触发。

## 12. 验收标准

### 12.1 流程验收

- D1-D14 仍能正常触发 Kofi、Victor、AEL 前置。
- D15-D30 每天有固定主线。
- D30 必定触发第一季结局。
- D30 后能进入 D31。
- D31 后能继续经营当前城市。
- D31 后能看到多城市入口。
- 至少 1 个新城市可进入经营。

### 12.2 多结局验收

- 至少 6 个第一季结局可达。
- 每个结局都有明确条件。
- 每个结局都读取选择账本。
- 每个结局都写入 D31 后续加成或代价。
- 玩家回顾页能看到关键选择。

### 12.3 弹窗验收

- 事件选择有弹窗。
- 事件选择后有结果弹窗。
- 点击结束今天后只出现一个今日总结弹窗。
- 不出现每日进入弹窗。
- 不出现每日结束后的额外剧情弹窗。
- 弹窗内容不需要纵向滑动。

### 12.4 升级体系验收

- 电脑/网络/电力/空调/安保至少各影响 1 个比赛或主线事件。
- 设施评分参与比赛结算。
- 设施路线参与 D30 结局分流。
- 首页能显示“今日推荐升级”。
- 玩家能理解升级和战队胜负有关。

### 12.5 多城市验收

- 结局后不强制重开。
- 结局后不强制转生清空。
- 当前城市资产保留。
- 新城市可进入。
- 城市切换、保存、读取正常。
- 第一季结局影响新城市开局。

## 13. 推荐实现顺序

第一阶段：UI 和事件反馈  
统一弹窗规则，事件选择后补结果弹窗，结束今天只保留一个总结弹窗。

第二阶段：选择账本  
接通 `ethics = {...}` 自动入账，补齐旧存档字段。

第三阶段：D15-D30 主线  
新增 `SeasonOneMainline.lua`，补 16 天强主线。

第四阶段：设施影响

第五阶段：Day30 多结局  
新增第一季结局页，至少 6 个结局，结局写入 D31 加成。

第六阶段：D31+ 多城市  
保留当前城市资产，打开新城市入口，至少 1 个新城市可经营。

第七阶段：QA  
重点测 D2 重复、D15-D30 主线、D30 结局、D31 继续、多城市保存读取、旧存档迁移。
